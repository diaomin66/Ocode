# Ocode 0.21.1 — Windows x64

## Public source and release channel

Ocode's source repository, [diaomin66/Ocode](https://github.com/diaomin66/Ocode), becomes public with the full upstream Git history, authorship and licensing preserved. Future Windows releases, downloads and the embedded updater use that same public repository.

The existing [v0.21.0 assets in Ocode-releases](https://github.com/diaomin66/Ocode-releases/releases/tag/v0.21.0) are immutable: they will not be replaced, renamed or republished as 0.21.1. The new release uses its own version, tag and update feed in `diaomin66/Ocode`.

## One manual upgrade from 0.21.0-beta.1

**Existing `0.21.0-beta.1` binaries require ONE MANUAL UPGRADE to 0.21.1.** They embed the old `diaomin66/Ocode-releases` feed and cannot discover the new release channel. Download `Ocode-Setup-0.21.1.exe` from the [0.21.1 release](https://github.com/diaomin66/Ocode/releases/tag/v0.21.1), quit Ocode and run the installer manually. ZIP and portable users must likewise download and replace their application files manually.

The application ID remains `com.ocode.desktop`. Your existing `.ocode` profile and `pi.sqlite` database are preserved. This release performs no automatic profile or data migration and does not copy, move or adopt upstream PI-Desktop profiles.

After that upgrade, the embedded updater uses `diaomin66/Ocode`. Installed NSIS builds default to automatic updates through the existing download/restart flow. ZIP and portable builds retain their manual-update default; existing saved update preferences remain respected.

## Unsigned Windows release

**Windows 0.21.1 remains unsigned.** The signing task was cancelled. Windows may show SmartScreen or **Unknown publisher** warnings for the installer or executables. No trusted publisher signature or signature verification is claimed, and signing credentials are not required for this release.

## Validation and scope

The Windows release workflow requires these checks before it publishes the packages. The attached `windows-verification.json` and `SHA256SUMS.txt` record the tested commit/base, boot results, unsigned status and artifact hashes:

- Build the Windows x64 artifacts, install NSIS on a disposable runner and boot both the installed application and extracted ZIP with isolated profiles. Verify their versions, distribution metadata, sandboxed preload and native Host RPC startup.
- Check that both embedded updater configurations use public `diaomin66/Ocode`, and that `latest.yml` references only the matching NSIS installer with its exact filename, size and SHA-512. Record artifact SHA-256 checksums and the tested commit/base.
- Bind the corresponding source archive and license to the tested commit, and verify the complete release asset set before publishing it.

Anonymous Release/feed access and real `electron-updater` discovery, download and hash validation are checked after publication; build-time feed checks alone do not establish public access. These checks do not install an automatic upgrade, qualify standalone portable EXE startup or establish SmartScreen reputation. macOS/Linux packages and remote Host bundles are outside this Windows release's qualification scope.

## Corresponding source and licenses

The public repository preserves the full corresponding source, upstream history, build configuration, dependency patches and licenses. Ocode retains PI-Desktop authorship and the LGPL-3.0-or-later license; dependencies retain their own licenses. See [LICENSE](../../LICENSE), [UPSTREAM.md](../../UPSTREAM.md) and [source build instructions](source-build.md).

The release must include `Ocode-Source-0.21.1.tar.gz` from the exact tested commit, with the full corresponding source, build scripts, dependency patches and licenses. The archive excludes `.git`, local profiles, private configuration and credentials; the public Git repository retains the complete history. Source completeness, license inclusion, artifact checksums and commit/base-bound verification evidence must be checked before publication.
