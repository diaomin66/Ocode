# Upstream attribution and Ocode identity

Ocode is a separately branded derivative of PI-Desktop by vastsa and its
contributors: https://github.com/vastsa/PI-Desktop.

The starting revision is `d940c8d` on the upstream `main` branch. This checkout
retains the upstream commit history, authorship and LGPL-3.0 license.
Third-party Pi engine packages, plugin APIs and dependency patches retain their
original identities. Historical screenshots and issue/commit references record
the upstream product; they are not new Ocode release evidence.

Ocode uses a different application ID (`com.ocode.desktop`), executable name,
workspace scope (`@ocode`), IPC prefix (`ocode/`), environment prefix (`OCODE_`)
and default profiles (`~/.ocode`, `~/.ocode-dev`, Electron `Ocode`/`Ocode Dev`).
It does not overwrite, delete, silently copy or automatically open the upstream
profile. Existing databases and credentials stay in their original location.
Use an explicitly chosen, backed-up copy when migrating data; encrypted
credentials may need reauthentication under the new application identity.
Do not run two different products against the same writable database.

Session links generated by Ocode use `ocode://`; old `pi-desktop://` links
remain readable. Plugin `engines.piDesktop`, the `pi.*` plugin API and `.piplug`
packages remain compatibility contracts, not product branding. The former
preload bridge name remains an alias with the same allowlist.
The plugin CLI is `ocode-plugin`, with `pi-plugin` retained as an alias.
The internal `pi.sqlite` name, plugin theme tokens, and Pi engine protocol
identifiers are retained for data and extension compatibility, not branding.
The existing upstream plugin marketplace remains an external ecosystem service.

The development and feedback repository remains `diaomin66/Ocode` (private).
Windows desktop releases and anonymous update feeds use the public
`diaomin66/Ocode-releases` distribution repository. Each release includes the
corresponding committed source snapshot, license, and build instructions;
private Git history and local configuration are not published. Earlier builds
that point to the private feed require one manual upgrade. Never embed GitHub
credentials in the application. Remote Linux Host bundles are not part of the
Windows-only release lane. The upstream-only CNB mirror stays disabled.

Historical brand references and unchanged dependency-patch comments are
intentional provenance exceptions. Product-facing text, package names and
build artifacts use Ocode. No claim is made that upstream screenshots were
recaptured for the fork.

All desktop installer patterns now use Ocode: `Ocode-Setup-<version>.exe`,
`Ocode-Portable-<version>.zip` / `.exe`, `Ocode-<version>-<arch>.dmg`,
`Ocode-<version>-<arch>-mac.zip`, `Ocode-<version>-linux-<arch>.AppImage`,
`ocode_<version>_<arch>.deb`, and `ocode-<version>-<arch>.rpm`.
Remote bundles are `ocode-host-<version>-linux-<arch>.tar.gz`, with
`ocode-host-core` / `ocode-host-core.exe` sidecars. The desktop and remote
Host must use matching Ocode versions, not upstream Host installations.

See [the identity decision](docs/adr/ocode-product-identity.md) for details.
